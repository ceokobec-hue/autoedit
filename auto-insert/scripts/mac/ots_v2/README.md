# OTS 카드 v2 — 자막 읽고 «자리·가독성»까지 스스로 정하는 부품

기존 `../build_inserts.py`(코너 카드 + 풀프레임)의 후속.
**⛔외부 파이썬 패키지 0 — ffmpeg 만 쓴다**(윈도우 이식 대비).

「OTS」는 방송에서 쓰는 말로 **Over-The-Shoulder** — 사람 어깨 옆에 붙는 그래픽이다.

## 카드 5종

| 종류 | 규격(QHD 기준) | 언제 |
|---|---|---|
| `sticker` 스티커 컷아웃 | 780×590 | 일상·에피소드. 흰 다이컷 테두리가 배경에서 카드를 떼어낸다 |
| `bento` 벤토 그리드 | 780×590 | **숫자 전용.** 값이 각자 색면을 가져 3초 컷에서도 읽힌다 |
| `rail` 세로 레일 | 470×1010 | 정보 3~5개 / 가로 자리가 안 나올 때. 사람은 가로로 서 있어 세로 띠는 잘 안 겹친다 |
| `daepan` 무판 대판 | 1700×430 | 큰 키워드 한 방. 판 없이 글자만. 3모드 자동 전환 |
| `terminal` 데이터 터미널 | 780×590 | 개발·기술 설명 구간 |

영상 해상도가 QHD(2560×1440)가 아니면 **가로 폭 비율로 전부 자동 환산**된다(`scale=영상폭/2560`).

# 실행 — 복붙해서 끝까지 가는 순서

## 준비

```bash
cd ~/Downloads/autoedit                       # ★ 모든 명령은 저장소 폴더 안에서
PY=~/.autoedit/venv/bin/python
S=$PWD/auto-insert/scripts/mac/ots_v2         # ← 절대경로로 잡아 둔다 (작업 폴더로 옮겨 갈 것이므로)

mkdir -p ~/ots-work && cd ~/ots-work          # 결과물이 여기에 쌓인다 (영문 경로)
```

작업 폴더에 **카드 원고 `cards.json`** 을 만든다(아래 스키마). 그리고 영상·자막 경로를 정한다.

```bash
VIDEO=~/촬영/자막구워진_영상.mp4              # ⛔ 자막이 «이미 구워진» 영상이어야 한다
SRT=~/촬영/자막.srt
```

## 1단계 — 자리·톤 재기

```bash
$PY $S/plan_cards.py "$VIDEO" cards.json      # → plan_out.json
```

카드마다 **5프레임을 표본**으로 떠서 「그 자리에 흰 글씨가 읽히나 / 검은 글씨가 읽히나」를 잰다.
카드는 5~8초 떠 있고 그동안 배경이 바뀌므로 **「최악의 순간」 기준**으로 판정한다.

화면에 나오는 표에서 `흰대비`·`검대비` 는 WCAG 명도 대비값이다. **4.5 이상이면 읽힌다.**

## 2단계 — 확정 (뺄 카드·금지 구간 반영)

```bash
$PY $S/approve.py --cards cards.json --plan plan_out.json
```
→ `check_cards.json` · `plan_check.json` · `plan_final.json`

여기가 **판정 결과를 「검수·렌더가 읽는 파일」로 굳히는** 자리다. 자주 쓰는 형태:

```bash
# 마음에 안 드는 카드 빼기
$PY $S/approve.py --cards cards.json --plan plan_out.json --drop D1,S3

# 카드가 «절대» 뜨면 안 되는 구간 (판서·중요 화면)
$PY $S/approve.py --cards cards.json --plan plan_out.json \
    --never "1:28-1:39" --never "11:32-끝"
```

| 인자 | 무엇 |
|---|---|
| `--drop D1,S3` | 이 카드들을 뺀다 |
| `--keep D1,S3` | **이것만** 남긴다 (`--drop` 과 같이 못 씀) |
| `--never "1:28-1:39"` | 카드가 **절대** 뜨면 안 되는 구간. 여러 번 쓸 수 있다. 「끝」도 쓸 수 있다 |
| `--must "5:00-6:00"` | 카드가 **있어야** 하는 구간. 비어 있으면 알려만 준다 |
| `--max-shift 15` | 금지 구간을 피해 뒤로 밀 수 있는 최대 초 (기본 15) |
| `--end 20` | 영상 길이(초). 「끝」을 쓰거나 영상 밖으로 밀리는 걸 막을 때 |

금지 구간에 걸린 카드는 **뒤로 밀어 보고**(최대 15초), 그래도 안 되면 **뺀다.**
뺀 카드는 화면에 목록으로 찍힌다 — **그냥 넘어가지 않는다.**

## 3단계 — 카드 PNG 굽기

```bash
$PY $S/cards_v2.py check_cards.json fin       # → fin/<id>.png (투명 배경)
```

Chrome 이 HTML 을 그려 PNG 로 뽑는다. 카드마다 ✅/❌ 가 찍힌다. **❌ 가 하나라도 있으면 멈추고 원인을 본다.**

## 4단계 — 🙋 검수 시트 (사람이 판정하는 자리)

```bash
$PY $S/build_sheet.py --video "$VIDEO" --srt "$SRT"
open 검수시트.html
```

**실제 화면에 카드를 얹은 그림**을 카드 수만큼 만들어 한 장으로 묶는다.
카드 옆에 「이 말에 붙습니다」로 그 순간의 대사가 함께 나와서, 내용이 맞는지도 같이 본다.

고칠 게 있으면 → `cards.json` 을 고치고 **1단계부터** 다시, 또는 빼기만 할 거면 `approve.py --drop`.

## 5단계 — 최종 렌더

```bash
$PY $S/render_ots_v2.py --video "$VIDEO" --out 완성본.mp4 --bitrate 24M
```

**한 패스로 굽는다.** 세대가 쌓이면 화질이 깎이고 QHD 중간본이 디스크를 먹는다.
⛔ 자막은 이미 원본에 구워져 있으므로 건드리지 않는다.

짧게 시험해 보려면 `--ss 300 --t 60` 을 붙인다.

## 파일이 어떻게 이어지나

```
cards.json ─plan_cards.py→ plan_out.json ─approve.py→ check_cards.json
                                                      plan_check.json  → build_sheet.py 🙋
                                                      plan_final.json  → render_ots_v2.py
check_cards.json ─cards_v2.py→ fin/<id>.png ──────────────────────────┘
```

| 파일 | 누가 만드나 | 누가 읽나 |
|---|---|---|
| `cards.json` | **사람** | `plan_cards.py` · `approve.py` |
| `plan_out.json` | `plan_cards.py` | `approve.py` |
| `check_cards.json` | `approve.py` | `cards_v2.py` · `build_sheet.py` · `render_ots_v2.py` |
| `plan_check.json` | `approve.py` | `build_sheet.py` |
| `plan_final.json` | `approve.py` | `render_ots_v2.py` |
| `fin/<id>.png` | `cards_v2.py` | `build_sheet.py` · `render_ots_v2.py` |

| 변수 | 무엇 | 기본값 |

## 파일

| 파일 | 하는 일 |
|---|---|
| `plan_cards.py` | 자리·톤 결정 + 금지구간 회피 + 카드 간 최소 간격 |
| `approve.py` | 판정 결과를 «검수·렌더가 읽는 파일»로 확정 (뺀 카드·민 카드를 알려 준다) |
| `cards_v2.py` | 카드 5종 렌더러. 해상도 자동 대응 |
| `bg_read.py` | 자리의 밝기·얼룩을 24×18 격자로 읽어 «흰/검은 글씨가 읽히나» 판정 |
| `build_sheet.py` | 검수 시트 HTML |
| `render_ots_v2.py` | 한 패스 최종 렌더 |
| `ink.py` | PNG에서 «글자 잉크»의 실제 사각 범위. 대판은 판이 없어 상자가 아니라 글자를 재야 한다 |
| `cell.py` | 번호 격자(4열×6행) ↔ 좌표. 대판 위치를 «번호»로 주고받는 공통 언어 |
| `make_grid.py` | 번호판 오버레이 PNG 생성 |

**분업이 핵심** — 내용 판단은 사람(또는 AI), 가독성 판단은 코드.
그리고 **코드가 그 결정을 거부할 수 있다**(원고상 무판이어도 배경이 안 받치면 스크림 추가 또는 판 있는 카드로 강등).

## 카드 계획 JSON 스키마

**아래 글자는 전부 자리표시자입니다.** 여러분 회차 내용으로 바꿔 쓰세요.
칸 설명은 [`파일형식.md`](../../../../파일형식.md) 에 표로 있습니다.

```json
{"id":"S1","kind":"sticker","at":34.6,"dur":5.5,
 "kicker":"작은 라벨","head":"큰 문구<br>두 줄까지","tag":"뱃지","emoji":"⚠️","emoji2":"💸",
 "rows":[{"t":"항목 이름","v":"값","unit":"만원"}],
 "foot":"아래 한 줄","src":"출처"}

{"id":"D1","kind":"daepan","at":111.3,"dur":6,
 "kicker":"작은 라벨","keyword":"큰 키워드","hi":"키워드"}
```

`daepan` 은 `keyword` 글자 수로 크기가 자동(≤5자 240px … 21자+ 106px).
`hi` 는 레드 강조 구간 — **줄바꿈으로 찢기지 않는다**(`white-space:nowrap`).

# ⛔ 실측·함정 (전부 실제로 당한 것)

아래 숫자는 **어떤 영상에서 재 본 한 예**다. 여러분 영상에서는 다르게 나온다.
값을 그대로 믿지 말고 **재는 방법**을 가져가면 된다.

## 1. 흰 글씨 무판은 밝은 배경 영상에서 거의 통과하지 못한다

배경이 밝은 실내 촬영본 70프레임을 전수로 재 본 예:

| 자리 | 무판 흰 글씨 | 무판 검은 글씨 | 얼룩져 무판 금지 |
|---|---|---|---|
| 좌 | **0/70** | 44/70 (63%) | 26 (37%) |
| 우 | **0/70** | 14/70 (20%) | 56 (80%) |
| 중앙 | **0/70** | **0/70** | 70 (100%) |

제일 어두운 프레임조차 흰 글씨 대비가 2.12로 미달이었다(4.5 이상이어야 읽힌다).
중앙은 사람이 서 있어 100% 얼룩.
→ **판 대신 「그늘(스크림)」을 깐다.** 그 영상에서 대비 1.05 → 6.29 (6배).

**여러분 영상에서는** `plan_cards.py` 가 같은 방식으로 재서 알려 준다. 표만 보면 된다.

## 2. 판정 영역은 «글자가 앉는 자리»여야 한다
카드 상자 전체로 재니 2.58(불합격), **실제 글자 자리**만 재니 6.29(합격).
하마터면 멀쩡한 방식을 「안 된다」고 버릴 뻔했다.

## 3. 한 프레임만 보면 안 된다
카드는 5~8초 떠 있고 그동안 배경이 바뀐다 → 스팬당 5프레임 표본, **최악의 순간** 기준.

## 4. ★프레임 캐시 키에 «시각»을 빠뜨리면 조용히 망가진다
`grab()` 파일명을 표본 번호(0~4)로만 지었더니 **모든 카드가 첫 카드의 프레임을 재사용**했다.
에러도 없고 숫자도 그럴듯했다. 알아챈 건 오직 **「장면이 다 다른데 값이 같을 리 없다」**는 상식 때문.
→ 자동 산출 표에서 **값이 다 똑같은 열**이 보이면 계산이 아니라 «복사»를 의심할 것.

## 5. 그늘 기하 — «중심 % ≥ 반지름 %» 아니면 칼자국이 남는다
`ellipse 52% at 42%` 는 왼쪽에서 0에 도달하기 전에 요소가 끝나 **하드 엣지**가 생긴다.
→ `ellipse 43% 46% at 44% 50%` + 여백 400px.

## 6. 그늘 세로 번짐이 자막을 덮는다
세로로 −250 이면 구워진 자막을 30% 덮는다 → **세로만 −150**.

## 7. 대판은 «아래 기준» 정렬이어야 한다
가운데 정렬이면 2줄짜리가 아래로 더 내려가 자막을 30px 침범한다.
→ `justify-content:flex-end; padding-bottom:50px` → 줄 수 무관하게 글자 아랫변 고정.

## 8. 세로 레일은 위에서 시작 좌표를 낮게 잡는다
y=200 에서 시작하면 200+1010=1210 이 되어 자막 윗변(1152)을 **침범**한다. y=118 이면 안 걸린다.

## 9. 크롬은 스크린샷을 다 쓰고도 안 죽는다
타임아웃을 꽉 기다리면 컷당 30초. **파일이 다 써졌는지**(크기가 두 번 연속 같은지)를 보고 죽이면 **2~4초**.

## 10. `ffprobe` 경로를 `replace('ffmpeg','ffprobe')` 로 만들면 깨진다
`/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg` → `/opt/homebrew/opt/ffprobe-full/bin/ffprobe`.
**경로에도 'ffmpeg'이 들어 있다** → `os.path.join(os.path.dirname(FF),'ffprobe')`.

## 11. 글자 폭을 «투영»으로 재면 가는 획이 묻힌다
`scale=iw:1:flags=area` 는 전 행 평균이라 얇은 획이 0으로 반올림된다.
안전 판정에서 과소측정은 위험 → **행 단위 직접 스캔**(`bytes.find`).

# 참고 성적 (M1 8GB 랩톱 · QHD 2560×1440 · 약 12분 영상)

여러분 맥에서는 다르게 나옵니다. **감을 잡는 용도**입니다.

- **최종 렌더 약 3분** · 24Mbps · **길이 오차 +0.000초** · 카드 16장 한 패스
- 카드 렌더 21장 ≈ 90초(크롬 조기 종료 적용 후)
- 구워진 본 자막 윗변 y=1152~1163 (Vision 24프레임 실측) → 글자 안전선 y=1139
- 얼굴 아랫변은 들쭉날쭉(594~1219) → **눈 띠(y380~700)만 피하면 된다**
