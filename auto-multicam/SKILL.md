# 오토멀티캠 (auto-multicam)

```
촬영(2대)  →  ★오토멀티캠  →  사용자가 컷 편집  →  오토인서트(자막·인서트)
```

**넣는 것은 영상 두 개**(+ 자막 한 개). 사람이 판정하는 곳은 **검토표에 체크 한 번**.

> 자막(SRT)과 낱말 시각 JSON 을 만드는 법은 [설치.md 부록](../설치.md#부록-자막srt와-문장-json-만들기) 에 있다.

> ⚠️ **지금은 1920×1080 촬영본을 전제로 한다.** 확대(zoom) 계산이 1920×1080 좌표로 되어 있어,
> 4K·QHD·720p 원본에 **확대가 걸린 후보가 하나라도 있으면** 그 프레임에서 ffmpeg 이 멈춘다.
> 확대 없이(전부 100%) 쓰면 다른 해상도에서도 돈다. 다른 해상도를 쓰시려면 미리 1080p 로 맞춰 두세요:
> ```bash
> $FF -i 원본.mp4 -vf scale=1920:1080 -c:v libx264 -crf 18 -c:a copy 1080p.mp4
> ```

## 이 스킬이 지키는 것

**① 싱크는 소리로 맞추고, 합격은 화면으로 판정한다.** 파형 상관계수가 높다는 건
"파형이 포개졌다"이지 "같은 순간이다"가 아니다. **반드시 두 카메라 프레임을 나란히 붙여 눈으로 본다.**

**② 여러 지점에서 잰다.** 카메라 두 대의 시계는 미세하게 다르게 간다(드리프트).
한 점만 재면 끝에서 어긋난다. 3~5지점의 (시각, 밀림)을 직선으로 맞춰 기울기까지 얻는다.

**③ 판서 판정은 사람이 한다.** 기계는 "화면이 이렇게 변했다"까지만 말할 수 있다.
그래서 후보마다 두 카메라 썸네일 + **추가된 글씨 그림**을 붙인 검토표를 내고 승인을 받는다.

**④ 상대 기준으로 판정하지 않는다.** "기울기 상위 38%" 같은 상대 기준은 실제 사건이 없어도
항상 38%를 뽑아낸다. **"글씨가 실제로 이만큼 늘었나"라는 실측 절대량**으로 거른다.

# 실행 — 복붙해서 끝까지 가는 순서

## 준비 — 한 번만

```bash
cd ~/Downloads/autoedit            # ★ 모든 명령은 저장소 폴더 안에서 친다
PY=~/.autoedit/venv/bin/python     # 파이썬은 «작은 방» 것을 쓴다 (설치.md 2단계)
FF=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg
S=auto-multicam/scripts/mac

W=~/multicam-work                  # 작업 폴더 — ⚠️ 영문 경로로 만든다(한글 경로에서 ffmpeg 이 넘어진다)
mkdir -p $W/sync $W/detect $W/plan $W/out
```

그리고 **어느 파일이 어느 카메라인지 한 번만 정한다.**

```bash
CAM1=~/촬영/고정캠.mp4              # ★ 메인 = 고정 삼각대 와이드캠 (판서가 보이는 쪽)
CAM2=~/촬영/컷인캠.mp4              #   컷인 = 짐벌·클로즈업캠
```

> ⛔ **소리가 어느 카메라에서 나왔는지와 「메인이 누구인지」는 별개다.**
> 「A 카메라 음성을 쓴다」 = 「A 가 메인」이 아니다. **메인은 판서가 보이는 고정캠**이다.
> 반드시 따로 확인할 것. 이걸 뒤집으면 영상 전체가 잘못된 카메라로 나간다.

## 1단계 — 싱크 (소리로 밀림을 잰다)

`sync_probe.py` 는 영상이 아니라 **16bit 모노 wav** 를 받는다. 먼저 소리만 뽑는다.

```bash
$FF -y -i "$CAM1" -vn -ac 1 -ar 16000 -c:a pcm_s16le $W/sync/A.wav
$FF -y -i "$CAM2" -vn -ac 1 -ar 16000 -c:a pcm_s16le $W/sync/B.wav

$PY $S/sync_probe.py $W/sync/A.wav $W/sync/B.wav --out $W/sync/sync.json
```

화면에 나오는 **`시작 밀림`** 값이 다음 단계들이 계속 쓰는 `--offset` 이다. 적어 둔다.

```bash
OFF=-2.5000                        # ← 방금 나온 「시작 밀림」 값을 그대로
```

> ⚠️ **짧은 영상은 `--win` 을 줄여야 한다.** 기본값은 한 지점에서 20초씩 떠서 대조하는데,
> 영상이 1분이 안 되면 잴 자리가 안 나와 `⛔ 측정 지점이 부족하다` 로 멈춘다.
> 시험용 20초 클립이라면 `--win 5`(필요하면 `--probes 5,10,15` 도) 를 붙인다.
> **실제 강의(수십 분)에서는 기본값 그대로 쓴다.**

- `전 구간 벌어짐` 이 0.033초 미만이면 → 단순 밀림 보정만으로 충분하다
- `⚠️ 직선으로 안 맞는다` 가 뜨면 → 카메라가 중간에 프레임을 흘린 것. 구간을 나눠 다시 잰다
- `⚠️ 일치도가 낮다` 가 뜨면 → 두 파일이 같은 현장 소리가 맞는지 먼저 의심한다

## 2단계 — 판독 (판서 영역의 좌표를 손으로 정한다)

기계는 「보드가 어디냐」를 모른다. 한 장 뽑아 눈으로 보고 정해 준다.

```bash
# 눈금이 그려진 프레임 한 장 (화면을 8×8로 나눈 선)
$FF -y -ss 300 -i "$CAM1" -frames:v 1 \
    -vf "drawgrid=w=iw/8:h=ih/8:t=2:c=red@0.8" $W/detect/grid.png
open $W/detect/grid.png

# 여러 시각을 한 장에 모아 보는 콘택트시트 (전체 분위기 확인용)
$FF -y -i "$CAM1" -vf "fps=1/60,scale=480:-1,tile=4x3" -frames:v 1 $W/detect/sheet.png
```

눈금을 보고 **보드만 들어가고 강사는 잘 안 들어오는 사각형**을 고른다.
그걸 `가로:세로:왼쪽에서:위에서` (픽셀) 로 적는다.

```bash
CROP=1120:1000:60:40               # 예: 왼쪽 60·위 40 지점부터 가로1120 세로1000
```

> ⛔ **크롭에 강사가 들어가면 안 된다.** 잉크량이 강사 몸에 끌려가 백지가 글씨판보다
> 높게 나온다. 강사가 평소 서지 않는 쪽으로 잡는다.
> ⛔ **감지는 고정 삼각대 카메라에서만.** 짐벌·얼굴추적 카메라는 화면이 늘 변해
> 27분 내내 "판서 중"이 된다.

## 3단계 — 맨 보드 만들기 (강사를 지운다)

```bash
DUR=$(/opt/homebrew/opt/ffmpeg-full/bin/ffprobe -v error \
      -show_entries format=duration -of csv=p=0 "$CAM1")
echo "영상 길이 $DUR 초"

$PY $S/board_bg.py "$CAM1" --crop $CROP --offset 0 --outdir $W/detect
```
→ `$W/detect/bgs.npy` · `$W/detect/board_bg.json`

같은 자리를 찍은 여러 장을 픽셀마다 **중앙값**으로 합치면, 지나가는 사람은 사라지고
움직이지 않는 것(보드와 글씨)만 남는다. 관광지에서 사람 없는 사진 만드는 그 원리다.

> `--offset` 은 **크롭한 영상의 시간축을 밀 때만** 쓴다. `$CAM1` 을 기준으로 잡았으면 `0` 이다.

## 4단계 — 판서 구간 뽑기

```bash
$PY $S/analyze_bg.py --dir $W/detect --dur $DUR
```
→ `$W/detect/board_segs.json` (판서·지움 구간)

화면에 1분 단위 잉크 곡선이 막대로 나온다. **글씨를 쓴 구간에서 막대가 올라가면 맞는 것**이다.
전 구간이 똑같이 높으면 크롭에 강사가 들어간 것 — 2단계로 돌아간다.

## 5단계 — 전환 후보 만들기 (둘 중 하나를 고른다)

| | `make_plan.py` | `shot_plan.py` |
|---|---|---|
| 입력 | **SRT** | **낱말 시각 JSON** (문장 재구성) |
| 결과 | 판서·지움 구간 위주로 **필요한 곳만** 전환 | 처음부터 끝까지 **촘촘한 샷 계획** |
| 언제 | 원본 리듬을 살리고 싶을 때 | 방송처럼 계속 바꾸고 싶을 때 |

### (가) SRT 로 — 간단한 쪽

```bash
$PY $S/make_plan.py --segs $W/detect/board_segs.json --srt ~/촬영/자막.srt \
    --dur $DUR --out $W/plan/cands.json --main 1
```

### (나) 낱말 시각으로 — 촘촘한 쪽

자막 큐를 그대로 컷 경계로 쓰면 **문장 한가운데서 잘려** 말이 끊긴 느낌이 난다.
그래서 낱말 시각을 이어붙여 문장을 다시 만든다. (JSON 만드는 법 → [설치.md 부록](../설치.md#부록-자막srt와-문장-json-만들기))

```bash
$PY $S/sentences.py --json ~/촬영/자막.json --out $W/plan/sentences.json --dur $DUR

$PY $S/shot_plan.py --sentences $W/plan/sentences.json --segs $W/detect/board_segs.json \
    --dur $DUR --out $W/plan/cands.json --main-cam 1 --ink $W/detect/board_bg.json
```

> ⚠️ `--json` 이 요구하는 건 평범한 whisper JSON 이 아니라 **낱말 시각(`t_dtw`)이 들어 있는**
> JSON 이다. whisper 를 `-nfa` 없이 돌리면 그 값이 전부 −1 로 비어서 나오고,
> **에러 없이 문장이 엉뚱하게 잘린다.**

## 6단계 — 🙋 검토표 (사람이 판정하는 자리)

```bash
$PY $S/build_review.py --cands $W/plan/cands.json \
    --camA "$CAM1" --camB "$CAM2" --offset $OFF \
    --bgdir $W/detect --sync $W/sync/sync.json \
    --names "고정캠,컷인캠" --main 1 \
    --out $W/plan/검토표.html
open $W/plan/검토표.html
```

후보마다 셋을 나란히 보여준다 — **지금 화면 / 바꾸면 이렇게 / 이 구간에 추가된 글씨**.
빨강이 새로 쓴 글씨, 파랑이 지운 글씨다. 10초면 판정된다.

체크한 결과를 다음 단계의 `--decide` 에 적는다. 형식은 `번호:확대%` 를 띄어쓰기로 나열.

```bash
DEC="1:135 6:135 10:120"           # 1번은 135% 확대로 살림 · 적지 않은 번호는 안 씀
```

> **`--decide` 를 아예 안 주면** 후보 중 `keep=true` 인 것(기본 켜짐)만 그대로 쓴다.
> 검토표를 열어 보긴 했지만 고칠 게 없으면 그냥 생략해도 된다.

## 7단계 — 렌더

**먼저 `--dry` 로 계획만 본다.** 렌더는 오래 걸리는데, 계획이 틀렸으면 그 시간이 통째로 버려진다.

```bash
$PY $S/render_multicam.py --cands $W/plan/cands.json \
    --camA "$CAM1" --camB "$CAM2" --offset $OFF --decide "$DEC" \
    --main 1 --work $W/out --out $W/out/멀티캠.mp4 --dry
```

구간 표가 그럴듯하면 `--dry` 만 빼고 다시 친다.

```bash
$PY $S/render_multicam.py --cands $W/plan/cands.json \
    --camA "$CAM1" --camB "$CAM2" --offset $OFF --decide "$DEC" \
    --main 1 --work $W/out --out $W/out/멀티캠.mp4
```
→ `$W/out/멀티캠.mp4` · `$W/out/switch_plan.json`

- **카메라 하나가 거울처럼 뒤집혀 찍혔으면** `--flip 2` 를 붙인다(칠판 글씨가 좌우 반대로 보이는 경우)
- 화질을 올리려면 `--bitrate 20M`

## 8단계 — 눈으로 검사

```bash
$PY $S/qa_sheet.py --video $W/out/멀티캠.mp4 --plan $W/out/switch_plan.json \
    --tmp $W/out/_qa --out $W/out/qa.png
open $W/out/qa.png
```

전환 지점 **앞뒤 0.25초**를 번호 붙여 뽑아 나란히 놓는다.
전체를 다 볼 수는 없지만 **잘못될 수 있는 곳은 정해져 있다** — 카메라가 바뀌는 순간이다.

**그리고 끝부분(마지막 1분)을 반드시 재생해 본다. 드리프트가 남았다면 거기서 드러난다.**

## 파일이 어떻게 이어지나 (한눈에)

| 단계 | 스크립트 | 먹는 것 | 내놓는 것 |
|---|---|---|---|
| 1 싱크 | `sync_probe.py` | `A.wav` `B.wav` | `sync.json` → **`시작 밀림` = 이후 `--offset`** |
| 2 판독 | (ffmpeg) | 영상 | 눈금 프레임 → **`--crop` 값** |
| 3 맨보드 | `board_bg.py` | 영상 + `--crop` | `bgs.npy` · `board_bg.json` |
| 4 분석 | `analyze_bg.py` | `--dir`(3의 폴더) | `board_segs.json` |
| 5 문장 | `sentences.py` | 낱말시각 JSON | `sentences.json` |
| 5 후보 | `make_plan.py` / `shot_plan.py` | `board_segs.json` + SRT 또는 `sentences.json` | **`cands.json`** |
| 6 검토 | `build_review.py` | `cands.json` + 영상2 + `bgdir` + `sync.json` | `검토표.html` 🙋 |
| 7 렌더 | `render_multicam.py` | `cands.json` + 영상2 + `--decide` | 완성 mp4 · `switch_plan.json` |
| 8 검사 | `qa_sheet.py` | 완성 mp4 + `switch_plan.json` | `qa.png` |

**JSON 안에 어떤 칸이 있는지**는 [`파일형식.md`](../파일형식.md) 를 본다.

## 함정 다섯 (전부 실제로 터진 것)

| 함정 | 증상 | 해결 |
|---|---|---|
| **움직이는 카메라에서 판서 감지** | 짐벌·얼굴추적 카메라는 화면이 항상 변해 27분 내내 "판서 중" | 감지는 **고정 삼각대 카메라에서만** |
| **크롭에 강사가 들어감** | 잉크량이 강사 몸에 끌려가 백지가 글씨판보다 높게 나옴 | 강사가 평소 안 서는 영역만 크롭 |
| **화면 전체 밝기로 잉크 측정** | 보드 가장자리 그늘·비네팅을 잉크로 셈 | **주변 25px 평균보다 어두운 점**만 (`analyze_bg.py` 의 상자 흐림) |
| **순간 장면변화(`gt(scene,..)`)로 판서 감지** | 지나가는 사람은 잡고 느린 글씨는 놓친다 — 정반대로 틀림 | **누적 잉크 곡선의 기울기** |
| **concat 목록에 상대경로** | `Impossible to open 'work/work/seg/s001.mp4'` | 목록 파일은 **절대경로**로 쓴다 |

## 함정 추가

| 함정 | 증상 | 해결 |
|---|---|---|
| 자막 큐를 그대로 컷 경계로 씀 | 문장 한가운데서 잘려 말이 끊긴 느낌 | 낱말 시각(`t_dtw`)으로 **문장** 재구성 (`sentences.py`) |
| 긴 문장은 문장 경계로 못 쪼갬 | 20초짜리 한 문장이 통째로 한 샷 | **문장 안의 숨 자리**(토큰 간 0.22초 이상)도 컷 후보로 |
| 먼저 시작한 카메라가 먼저 끝남 | 마지막 조각이 몇 프레임 모자라 길이 불일치 | **두 카메라가 겹치는 구간까지만** 만든다 |
| `drawtext` 안의 `%` 와 `:` | `Stray %` · `No option name near` | `expansion=none` + 시각은 `01m05s` 표기 |
| whisper base 한국어 | 「취합」→「치압」 등 오인식 | **small 이상** 권장 (27분에 100초) |
| **카메라가 미러 모드로 저장** | 칠판 글씨가 «거울글씨». 짐벌·포켓형 카메라를 셀피 방향으로 찍으면 생긴다 | `hflip` 을 **자르기보다 먼저** 적용 (`--flip 2`) |
| 두 카메라의 인물 위치가 반대쪽 | 컷마다 사람이 좌우로 튄다(축 넘기) | 미러 교정하면 대개 같이 해결된다 |
| 1080p 가 아닌 원본에 확대를 검 | `Nothing was written into output file` (검토표·렌더가 죽는다) | 원본을 1920×1080 으로 맞추거나, 확대를 전부 100% 로 |
| 짧은 클립으로 싱크를 잼 | `⛔ 측정 지점이 부족하다` | `--win 5 --probes 5,10,15` 로 줄인다 (1분 미만일 때만) |

## 렌더 규약 (코드를 고칠 때 지킬 것)

- 모든 조각을 **똑같은 인코더 설정**으로 굽는다(`venc()`). 하나라도 다르면 `concat -c copy` 가 깨진다
- 경계를 **프레임 번호**로 다루고 `-frames:v` 로 장수를 지정한다. 초로 다루면 오차가 쌓인다
- fps 가 다른 카메라는 `fps=30000/1001` 로 기준 카메라에 맞춘다
- **소리는 기준 카메라 것을 통째로 `-c:a copy`.** 자르지 않으므로 튈 곳이 없고 음질 손실도 없다
- 조각은 이어붙이는 즉시 삭제한다 (긴 영상은 중간 파일이 디스크를 금방 채운다)

## 검증 (숫자로 재고, 화면으로 판정한다)

렌더 프레임이 원본 몇 초와 맞는지 **픽셀 차이로 잰다**. ±1프레임에서 차이가 몇 배로 튀면 정확한 것.
확대가 걸린 구간을 눈으로 원본과 비교하면 «다른 순간»으로 착각한다 — 구도가 달라지기 때문. 반드시 잰다.

끝부분(마지막 1분)을 반드시 본다. **드리프트가 남았다면 거기서 드러난다.**

## 편집 취향 — 기본값을 이렇게 잡은 이유

- **메인 = 고정 삼각대 와이드캠**(판서가 보이는 쪽). 짐벌 클로즈업캠은 «컷인 전용».
- **확대는 메인 카메라만.** 컷인 카메라는 각도가 이미 달라서 확대가 필요 없다.
- **한두 문장마다 전환** — 샷 평균 8초·범위 3~13초. 자막(문장) 단위로 자른다.
- 소리 출처와 메인 카메라는 **별개다.** 반드시 따로 확인할 것.

취향이 다르면 `shot_plan.py` 의 `--short` `--long` `--max` 로 바꾼다.

## 박자가 뻔해지지 않게 — 네 번 실패하고 얻은 것

| 시도 | 결과 |
|---|---|
| 직전 샷으로 다음을 정함 | 상태기계가 되어 `W→M→D` **3박자 61%** |
| 확대를 118/132/135% 로 잘게 나눔 | 크기가 비슷해 **점프컷**(실수처럼 보임) |
| 매 경계마다 무조건 그림을 바꾸라 강제 | 바꿀 이유가 없는데 바꾸니 `W↔Z` **62% 교대** |
| 억지 교대를 아예 없앰 | 판서 구간이 한 그림으로 뭉쳐 **114초짜리 샷** |
| ✅ **「한 그림이 이어진 시간」을 관리** | 이유가 있으면 바꾸고, 없어도 11초 넘으면 바꾼다 → 상위3 패턴 55% |

**★ 카메라가 두 대면 A↔B 교대 자체는 정상이다.** 단조로움은 «길이의 불규칙»(문장 구조에서 옴)과
«가끔 한 카메라에 2~3샷 머무는 변주»로 깬다. 억지 교대는 오히려 박자를 만든다.

**★ 같은 카메라에서 비슷한 크기로 자르면 컷이 아니라 실수로 보인다.** 30% 이상 차이를 두거나
카메라를 아예 바꾼다. 100% ↔ 135% 는 제대로 컷으로 읽힌다.
