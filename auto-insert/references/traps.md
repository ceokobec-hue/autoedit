# 조용히 망가지는 함정 목록

전부 **실측**이다. 공통점 하나 — **에러가 안 난다.** lint 통과, 콘솔 0, "성공" 메시지, 길이·해상도 검증까지 통과한 뒤에 산출물만 틀려 있다. 그래서 이 목록의 절반은 "눈으로 봐라"로 끝난다.

## 1. PowerShell 변수명은 대소문자를 안 가린다 ★가장 비쌌던 것

스크립트 파라미터 `$Src`와, 그 안에서 dot-source 하는 설정 파일의 `$SRC`는 **같은 변수**다. 설정을 불러오는 순간 파라미터가 덮인다.

**실제로 터진 것**: 인서트 마스터를 잘라야 하는데 편집 원본을 잘라서, **47컷 전부가 강사 촬영본 조각**이 되었다. 개수·해상도·길이·코덱 전부 정상. 합성까지 성공하고 길이 오차 0초가 나왔다.

**대응**
- 파라미터를 받은 즉시 다른 이름의 지역변수로 복사한 뒤 설정을 불러온다
  `param($Master)` → `$MasterPath = $Master` → `. plan.ps1`
- 설정 변수에 접두어를 붙인다 (`$EP_SRC`, `$EP_OUT`)

## 1-b. 배열 리터럴 안의 산술식은 괄호로 묶는다

```powershell
$ov += ,@([double]$c.ts, [double]$c.ts + [double]$c.d, $c.id)   # ⛔
```
PowerShell이 `[double]$c.ts + [double]$c.d` 를 **두 원소로 쪼갠다.** 결과는 `[436, 436, 5, 'INS-18']` — 끝 시각 자리에 시작 시각이 들어간다.

**에러가 안 난다.** 겹침 검사가 `끝 시각` 대신 `시작 시각`을 비교하게 되어 **무엇도 잡지 않으면서 "✅ 겹침 없음"을 출력한다.** 검사기가 조용히 죽는 것이 가장 위험하다.

```powershell
$ov += ,@( ([double]$c.ts), ([double]$c.ts + [double]$c.d), $c.id )   # ✅
```

**검사기에는 반드시 자기 검증을 붙인다** — 원소 수가 예상과 다르면 즉시 중단. 그리고 **일부러 위반시킨 입력으로 음성 테스트**를 한 번 돌려, 검사기가 실제로 잡는지 확인한 뒤 신뢰한다.

## 1-c. `return ,@(...)` — 배열이 한 겹 더 감싸진다

```powershell
function Split-Line([string]$t) { return ,@($t) }    # ⛔ $lines[0].GetType() = Object[]
function Split-Line([string]$t) { return @($t) }     # ✅ 문자열
```

`@(Split-Line $t)` 로 받아도 원소가 **문자열이 아니라 배열**이다. `$lines[$i].IndexOf($word)` 는 배열의 IndexOf 로 조용히 `-1` 을 뱉고, 폭 계산은 `[string]` 캐스팅으로 그럴듯한 숫자를 낸다.

**실제로 터진 것**: 자막 ASS 938줄이 정상 생성되고 파일 크기도 멀쩡했는데 **두 줄 분할 0건 · 형광펜 75개 전부 실패**였다. 마지막 줄에 처리 건수를 찍어 두지 않았다면 최종 영상까지 갔다.

**대응 — 배열을 다루는 스크립트는 끝에 처리 건수를 출력한다.** `자막 938개 · 두 줄 32개 · 강조 75개`. 0이 뜨면 즉시 보인다. 이 습관 하나가 위 셋을 전부 잡는다.

## 1-d. 사본을 뜨면 dot-source 경로부터 바꾼다

작업 폴더를 복사해 새 폴더를 만들었는데 `compose1~3.ps1`이 여전히 **옛 폴더의 `plan.ps1`** 을 읽고 있었다. 그대로 돌렸으면 **새로 렌더한 인서트가 아니라 옛 인서트로 합성**된다. 길이·용량·해상도 검증은 전부 통과한다.

**사본을 뜬 직후 dot-source 줄(`. "…\plan.ps1"`)을 전부 훑어 경로를 새 폴더로 바꾼다.**

## 1-e. `` `v `` 는 수직 탭이다

```powershell
"$st`vstack=inputs=3"      # ⛔ ffmpeg: No such filter: 'stack'
"$st" + "vstack=inputs=3"  # ✅
```
PowerShell 큰따옴표 안에서 백틱+문자는 이스케이프다. `` `v ``(수직 탭), `` `t ``(탭), `` `n ``(줄바꿈), `` `b ``, `` `r `` 모두 해당한다. **필터 이름·경로가 백틱 뒤에 오면 문자열을 잘라 이어 붙인다.**

## 2. 용량이 가장 빠른 이상 신호

정지 그래픽은 실사 영상보다 **20배쯤 작다.** 인서트 47컷(약 4분)이

- 정상 **16.7 MB**
- 이상 **312 MB** ← 촬영본을 자른 것

**분할·렌더 직후 합계 용량부터 본다.** 프레임을 뽑기 전에 잡을 수 있는 유일한 자동 신호다.

## 3. t=0에 걸린 tl.set은 첫 프레임에 적용되지 않는다

HyperFrames에서 `tl.set(..., 0)`으로 준 초기 숨김 상태가 **정확히 0초에는 렌더되지 않는다.** 첫 씬의 첫 프레임이 통째로 비거나, 숨겼어야 할 것이 다 보인다.

**대응** — 타임라인 앞에 **0.5초 패드**를 두고 첫 씬을 0.5초부터 시작시킨다. 분할할 때 패드를 잘라낸다. 이러면 이 계열의 문제가 전부 사라진다.

## 4. `@property`로 등록한 변수명에 다른 타입을 넣으면 조용히 초기값이 된다

`--tx`를 `<length>`로 등록해 놓고 팔레트에서 `--tx: #F7EFE0`(색)으로 쓰면, 타입 불일치라 **에러가 아니라 initial-value(0px)로 대체**된다. `color: 0px`은 무효 → 글자가 배경색으로 사라진다.

예약 이름: `--fx --fy --tx --ty --fr --fre --fo --to --dl --c0 --c1`
**팔레트 변수는 이 이름을 피한다.** 텍스트 색은 `--txt`.

## 5. 애니메이션이 걸린 래퍼는 스택 컨텍스트를 만든다

래퍼 바깥에 둔 오버레이(틴트·하이라이트·형광펜)는 z-index를 아무리 낮춰도 **래퍼 안 요소보다 위에** 그려진다. 덮개류는 **반드시 해당 묶음 안에** 넣는다.

같은 계열:
- **자식의 `animation-delay`는 부모 기준이 아니라 문서 전역 기준이다.** 부모가 2.8초에 뜬다고 자식에 `0s`를 주면 이미 끝나 있다
- **`<span>` 안에 `display:block` 자식을 넣으면 인라인 박스가 무너진다.** 배경이 좁은 띠로만 그려지고 글자가 밖으로 나간다 → `display:inline-block`
- **같은 페이지에 `id` 중복 금지.** 앵커도 깨지고 Playwright 선택자도 터진다

## 6. 세로로 나열한 카드는 간격을 안 벌리면 한 덩어리로 읽힌다

카드 5장을 높이 120·간격 100으로 놓으면 20px씩 겹쳐 **기둥 하나**로 보인다. 높이 80·간격 100으로 벌려야 다섯 장으로 읽힌다.

## 7. 좌상단 로고는 페이드 없이 첫 프레임부터 켠다

인서트에서 범퍼로 하드컷될 때 **로고만 페이드로 들어오면 컷 순간 깜빡인다.** 로고·귀속·회차 표기는 트윈을 걸지 않는다.

## 8. 한글이 들어간 `.ps1`은 UTF-8 **BOM**이 필수

BOM 없이 저장하면 PowerShell 5.1이 ANSI로 읽어 한글이 깨지고 파서 에러가 난다. 작성 후 반드시 BOM으로 변환한다.

```powershell
$t=[IO.File]::ReadAllText($p,[Text.UTF8Encoding]::new($false))
[IO.File]::WriteAllText($p,$t,[Text.UTF8Encoding]::new($true))
```

## 9. ffmpeg는 한글 경로에서 자주 넘어진다

작업 폴더는 **영문 경로**(`~/multicam-work`, `D:\work\...`)를 쓰고, 완성본만 한글 폴더로 옮긴다. 한글 파일명이 필요하면 ASCII 임시명으로 뽑은 뒤 rename 한다.

## 10. `-ss`를 `-i` 앞에 두면 자막 타임코드가 0으로 리셋된다

`ffmpeg -ss 600 -i v.mp4 -vf subtitles=sub.ass` 는 600초 지점 영상에 **0초부터의 자막**을 붙인다. 시험 굽기 때만 나타나므로 헷갈리기 쉽다. 본 굽기에서는 `-ss`를 안 쓰므로 문제없다.

## 11. libass는 웹폰트(woff2)를 못 읽는다

자막을 구우려면 **시스템에 설치된 폰트나 OTF/TTF 파일**이 있어야 한다. Pretendard가 시스템에 없으면 맑은 고딕으로 대체돼 인서트와 글꼴이 달라진다.

**대응** — OTF를 받아 두고 `subtitles=...:fontsdir=` 로 지정한다.
`https://cdn.jsdelivr.net/npm/pretendard@1.3.9/dist/public/static/Pretendard-Bold.otf`
(GitHub raw는 자주 끊긴다. jsDelivr **npm** 경로를 쓸 것 — gh 경로는 404)

## 11-b. ASS `Fontname`은 파일명이 아니라 **패밀리 이름**이다

`Style: Base,Pretendard-Bold,...` 라고 쓰면 libass가 그런 패밀리를 못 찾아 **조용히 기본 폰트로 폴백**한다. 경고도 에러도 없다. 올바른 값은 `Pretendard`다.

패밀리 이름은 파일에서 직접 읽는다 — `GlyphTypeface.FamilyNames.Values` 첫 항목.

같은 맥락으로 **Bold와 Black은 패밀리가 같아 `Fontname`으로 구별되지 않는다.** 굵기는 Bold 플래그로 libass가 고른다. 글자체를 진짜로 바꾸려면 **다른 패밀리**의 OTF/TTF를 폰트 폴더에 넣어야 한다.

## 11-c. 폰트 폴더의 깨진 파일

`Pretendard-Black.ttf`가 **120바이트**짜리 껍데기로 들어 있었다. 로드에 실패하면 폴백되고, 역시 아무 말이 없다. 후보를 훑을 때 **50KB 미만 파일은 걸러낸다.**

## 11-d. 받은 SRT의 한 구간만 영어일 수 있다

20초쯤 되는 한 구간(13줄)이 **받은 SRT 원본부터 영어**였다. 받아쓰기 도구가 그 구간만 «번역»해 버린 것이다. 앞뒤는 멀쩡한 한국어라 통째로 훑지 않으면 못 본다.

**시작할 때 라틴 문자로만 된 큐를 세어 본다.** 몇 개 있으면 그 구간 오디오만 잘라 다시 받아쓴다.

```bash
python3 -c "
import re,sys
n=sum(1 for b in re.split(r'\n\s*\n', open('자막.srt',encoding='utf-8-sig').read())
      if (t:=' '.join(b.strip().split(chr(10))[2:])).strip() and not re.search(r'[가-힣]', t))
print('한글이 하나도 없는 큐:', n, '개')"
```

**받아쓰기를 다시 할 때 `task="transcribe"`(번역이 아니라 «받아쓰기»)를 명시**하지 않으면 같은 사고가 재발한다.
교체할 때 **앞뒤 경계 시각은 고정** — 밀리면 인서트 전 컷이 어긋난다.

## 12. 검증이 통과해도 내용은 틀릴 수 있다

`ffprobe`로 개수·해상도·길이·코덱을 다 맞춰도 **"엉뚱한 그림이 들어갔다"는 절대 안 잡힌다.** 위 1번이 정확히 그랬다.

**단계마다 프레임을 뽑아 콘택트시트로 본다.** 이게 이 파이프라인에서 가장 값어치 있는 검증이다.
