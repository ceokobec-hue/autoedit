# 오토인서트 (auto-insert)

컷편집이 끝난 강의 영상에 **인서트컷·범퍼·자막을 얹어 완성본 한 편**으로 만든다.

```
컷편집  →  ★오토인서트  →  완성본
```

**입력은 두 개뿐이다** — 자막 없는 mp4 + SRT.
**사용자 개입은 한 번뿐이다** — 컷리스트 검토표에 × 표시.

## 이 스킬이 지키는 것

**① 판서·화면을 덮지 않는다.** 강사가 화이트보드에 쓰고 있거나 손으로 가리키는 순간을 풀프레임 인서트가 덮으면 수업이 통째로 날아간다. 그래서 **보호 구간이 항상 인서트보다 우선**이다.

**② 화면 글자가 대사를 복제하지 않는다.** 같은 말을 귀로 듣고 눈으로도 읽으면 오히려 안 읽힌다. 대사는 흐르고 화면은 요약된 명사만 남긴다.

**③ 판서와 중복하지 않는다.** 강사가 칠판에 「결과물」이라 쓰는데 인서트도 「결과물」을 크게 띄우면 같은 말이 세 번 나온다. 인서트는 **판서가 못 보여주는 것**(장면·비유·계보·대조)을 맡는다.

**④ 검증은 반드시 눈으로 한다.** 길이·해상도·개수 검증은 "내용이 틀린 것"을 절대 못 잡는다. 단계마다 콘택트시트를 뽑아 본다. → `references/traps.md`

## 배경이 바뀌는 영상은 「방송형 오버레이」로 간다

야외 촬영·이동 촬영처럼 **배경이 계속 바뀌면** 풀프레임 인서트만으로는 안 맞는다.
좌상단 **채널 버그** + **단원 소제목** + 어깨 옆 **코너 카드(OTS)** 로 간다. → `references/broadcast-overlay.md`

**핵심 세 줄**
- **얼굴만 회피하고 어깨는 덮는다.** 어깨까지 피하면 셀피 영상에서 카드가 680px로 쪼그라든다
- **편집자가 넣은 강조자막·강의장 슬라이드도 회피 대상이다**(높이 60px 이상 글자 전부)
- 자리가 없으면 시각을 15초까지 밀고, 그래도 없으면 **풀프레임으로 승격**(원고를 3항목으로 보강할 것)

**🙋 검수 게이트는 기본값이다.** 전체 렌더 전에 **필요한 프레임만 구워 번호표를 붙인 시트**를 내고,
사용자가 「4번, 17번 고쳐」처럼 번호로 지적 → 수정 → 재발행 → **명시 승인 후에만** 최종 렌더한다.

## Phase 0 — 컨텍스트 확인

작업 폴더를 확인해 실행 모드를 정한다.

| 상태 | 모드 |

## Phase 1 — 입력 판독 (자동)

사용자가 mp4와 SRT 경로를 주면 **묻지 말고 바로 읽는다.**

1. **규격 대조** — 해상도·fps·길이·오디오, SRT 큐 수와 마지막 타임코드
   - **SRT 끝 시각과 영상 길이 차이가 0.5초를 넘으면 중단하고 알린다.** 컷편집을 더 손댄 뒤 SRT를 안 뽑은 것이다. 이 상태로 진행하면 47컷이 전부 어긋난다.
2. **자막 유무 확인** — 프레임을 몇 장 뽑아 하단에 글자가 이미 있는지 본다. 있으면 알리고, 그대로 갈지 무자막 재export를 받을지 묻는다.
3. **화면 구성 판독** — 10장쯤 균등 샘플링해 콘택트시트로 본다. 이게 설계를 좌우한다.

| 구성 | 판단 | 결과 |
|---|---|---|
| 화면공유 + 캠 PIP | 좌상단이 캠 자리 | 오버레이 가능, 좌상단 회피 |
| **화이트보드 강의 원샷** | 판서가 시각자료 역할 | **풀프레임 위주**, 판서 단어 수집 후 중복 회피 |
| 슬라이드 전체화면 | 슬라이드가 시각자료 | 인서트 밀도를 낮춘다 |

4. **판서 단어 수집** — 화이트보드형이면 프레임에서 강사가 쓴 단어를 읽어 목록화한다. 그 단어는 인서트에서 다시 크게 띄우지 않는다.
5. **스타일** — 시리즈 고정이면 묻지 않는다. 신규 시리즈면 먼저 스타일부터 정한다.

## Phase 2 — 설계 (SRT만으로 됨 · 영상 없어도 가능)

`scripts/srt_tools.ps1`(맥·리눅스는 `scripts/mac/srt_tools.py`)로 수행한다.
**영상 렌더를 기다릴 필요 없이 이 단계를 먼저 끝낼 수 있다.**

1. **블록 스캔** — 20초 단위로 대사를 묶어 서사 구조를 파악한다
2. **앵커 탐색** — 각 컷의 근거 문장을 키워드로 찾아 **정확한 큐 시작 시각**을 얻는다. 삽입 지점은 반드시 **큐 경계**여야 한다. 문장 한가운데는 어색하다
3. **컷리스트 초안** — 24분 기준 **40~50컷**(30초에 한 컷꼴). 설계 규칙과 레이아웃 5종은 `references/cutlist-design.md`
4. **범퍼 배치표** — 삽입/덮어쓰기 구분. 세트 구성은 `references/bumper-set.md`
5. **보호 구간 반영** — 아래 참조
6. **정합성 검사** — `scripts/plan_check.ps1`. 덮어쓰기 구간 겹침, 삽입점이 인서트 내부에 떨어지는지, 보호 구간 침범 여부. **하나라도 걸리면 진행하지 않는다**
7. **유튜브 챕터** 타임스탬프 산출

### 보호 구간 (살릴 구간)

사용자가 「07:20~07:35 판서 살려」처럼 지시하면 그 구간은 강사 화면이 그대로 나간다.

```
① 그 구간엔 인서트를 놓지 않는다
② 걸치는 컷은 앞뒤로 밀거나 짧게 자른다
③ 밀 자리가 없으면 그 컷을 뺀다      ← 보호가 항상 이긴다
④ 범퍼 삽입점도 그 안으로 못 들어간다
```

**자동 보호 후보 제안**: 화이트보드 영역만 잘라 프레임 변화량을 재면 새 글씨가 늘어나는 구간이 나온다. 그걸 후보 목록으로 먼저 드리고 × 표시를 받으면, 사용자가 초 단위로 찾아 적을 필요가 없다. → `scripts/detect_writing.ps1`

### 검토 게이트 ① — 컷리스트

컷리스트·범퍼 배치·보호 구간을 **HTML 검토표 한 장**으로 만들어 브라우저로 띄운다. 각 줄에 「빼기」 체크칸, 보호 구간은 색으로 표시. 사용자는 **× 표시만** 하면 된다.

### 검토 게이트 ② — 자막 스타일 (`scripts/style_gate.ps1`)

**색·글자체·크기를 고정값으로 정하지 않는다.** 회차마다 화면이 다르고 입은 옷이 다르다. 실측해서 후보를 만들고 **실제 프레임에 얹은 스크린샷으로 결재**받는다.

```powershell
style_gate.ps1 -Mode analyze -Video v1.mp4 -Out {작업폴더}   # 실측 → 후보 → 비교 시트 4장
# ⛔ 자동으로 고르지 않는다 — 비교 시트 4장을 사용자에게 열어 보이고 번호를 받는다
style_gate.ps1 -Mode commit -Out {작업폴더} -Size 130 -BoxPick 1 -EmphPick 1 -FontPick 1
```

| 축 | 어떻게 뽑나 |
|---|---|
| 배경 박스 | 의상색 톤온톤 · 시리즈 고정색 · 중립 딥차콜. **흰 글씨 대비 4.5:1 미만은 걸러낸다**(반투명이라 아래 화면과 섞은 색으로 계산) |
| 강조 글자색 | 앰버 · 시리즈 오렌지 · 라이트 시안 |
| 크기 | 120 / 130 / 140 |
| 글자체 | `FontDir` 안에서 실제로 열리는 파일. **같은 패밀리는 하나로 묶는다** — ASS `Fontname`이 같으면 libass가 Bold 플래그로 고르므로 Bold/Black을 따로 내밀어도 화면에서 구별되지 않는다 |

확정값은 `{작업폴더}\caption_style.json`에 남고 `make_ass.ps1 -StyleJson`으로 물린다. 부분 재실행 때 같은 스타일이 그대로 재현된다.

두 게이트를 통과하면 **제작·합성·납품까지 멈추지 않는다.**

## Phase 3 — 제작

1. **인서트** — `assets/insert-engine.html`을 복사해 **데이터 배열만 채운다.** 47컷을 손으로 쓰지 않는다. 레이아웃 5종(hero/list/vs/chain/stack)에 데이터를 넣으면 생성기가 DOM과 타임라인을 만든다. **한 곳을 고치면 모든 컷에 동시 반영**된다
2. **범퍼** — 시리즈 고정 자산. 회차마다 **글자만 교체**해 재렌더한다
3. **렌더** — 1080p로 작성하고 `--resolution landscape-4k`로 렌더한 뒤 lanczos로 QHD 축소. HyperFrames는 정수배 프리셋만 지원하므로 QHD 직접 렌더가 안 되고, 이 방식이 더 깨끗하다
4. **분할** — `scripts/split_master.ps1`

**렌더 직후 반드시 확인:**
- 콘택트시트로 전 컷 육안 검증
- **합계 용량** — 정지 그래픽 4분이 촬영본급(수백 MB)이면 잘못된 소스를 자른 것이다. 정상은 수십 MB. → `references/traps.md`

## Phase 4 — 합성 (순서가 규약)

```
1 인서트 덮어쓰기  →  2 자막 굽기  →  3 범퍼 삽입
```

**범퍼가 마지막인 것이 규약이다.** 범퍼는 시간을 밀어내므로, 자막을 나중에 구우면 자막 수백 개의 타임코드를 전부 다시 계산해야 한다. 인서트와 자막을 **원본 타임라인에서 먼저 끝내면 계산이 아예 필요 없다.**

**자막은 네 층을 2단계에서 한 번에 굽는다** — 배경 박스 · 키워드 띠 · 글자(강조 포함) · 말풍선. 나중에 하나를 따로 얹으면 자막→범퍼를 통째로 다시 돌려야 한다. 실제로 형광펜 층을 나중에 만들다가 못 넣고 납품한 적이 있다.

`scripts/pick_emphasis.ps1`(무엇을 강조할지) → `scripts/make_ass.ps1`(전부 한 파일로). 규격은 `references/caption-style.md`.

**강조는 띠가 아니라 글자색이다.** 띠는 좌표를 계산해야 해서 폭이 몇 px만 어긋나도 옆 글자를 침범했다. 색은 계산할 좌표가 없다 — 브라우저 실측 단계가 통째로 사라졌다.

ffmpeg 명령과 각 단계 규약은 `references/composite-pipeline.md`.

**단계마다 콘택트시트를 뽑아 본다.** 특히 1단계 직후 — 인서트가 제자리에 붙었는지는 눈으로만 확인된다.

## Phase 5 — 납품

1. 완성본을 `{작업폴더}/{회차}_완성본_{YYYY-MM-DD}/` 에 낸다 (이름 규칙은 취향대로)
2. 문서 동봉 — 컷리스트·배치표·큐시트·manifest.json
3. **rclone으로 Drive 업로드 후 로컬/원격 파일 개수를 대조**한다. 개수만 봐도 누락이 잡힌다
4. 브라우저로 완성본을 띄운다
5. SEO 패키지가 필요하면 챕터 타임스탬프를 그대로 넘긴다

**모바일 확인본은 기본으로 만들지 않는다.** 「모바일본 뽑아줘」라고 할 때만 720p ~180MB로 뽑아 함께 올린다.

### 납품 뒤 — 피드백을 반드시 여쭙는다

완성본을 띄운 뒤 **다섯 축을 짚어** 여쭙는다 — 자막 **크기** / **강조**가 눈에 들어왔는지 / **배경** 농도 / **줄바꿈**이 어색한 곳 / 말과 자막 **타이밍**. 받은 답은 `references/caption-style.md` 이력표에 누적한다. 회차가 쌓일수록 게이트가 내미는 후보가 그 사람 취향에 수렴한다.

**이 단계를 건너뛰지 않는다.** 자막이 작다는 것도, 형광펜이 자간을 넘는다는 것도 여쭤봐서 알았다.

## 테스트 시나리오

**정상 흐름** — 「오토인서트. 편집 원본.mp4랑 srt 줄게」 → 규격 대조(싱크 오차 보고) → 화면 구성 판독 → 컷리스트 47컷 + 범퍼 배치표 검토표 → 사용자 × 표시 → 제작 → 3단계 합성 → Drive → 완성본 재생

**에러 흐름** — SRT 끝 시각이 영상보다 12초 짧음 → **Phase 1에서 중단.** "컷을 더 손보신 뒤 SRT를 다시 뽑아 주세요"라고 알리고, 그 상태로 진행하지 않는다. 억지로 진행하면 모든 컷이 어긋나고 되돌리려면 전부 다시 만들어야 한다
